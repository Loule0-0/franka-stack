# 安全与分阶段放行

这是一份工程检查表，不替代 Franka 手册、现场风险评估和组织安全制度。最终控制权和是否放行运动始终由现场操作者承担。

## 1. 不可由软件替代的保护

- 机械臂固定在符合厂家要求的稳定底座上，电缆和末端执行器安装正确。
- 按现场风险评估配置隔离区、限速、碰撞阈值和必要的安全设备。
- 操作者能立即触达已验证的停止装置，并有另一名观察员在场。
- Franka 的 external activation device（EAD）保持可触达。官方特别说明：EAD **不是 emergency stop**，不能把它当成唯一急停措施。
- Desk 中的末端质量、质心和惯量与真实工具一致；错误载荷会影响重力补偿与碰撞行为。
- 首次运动移走桌面物体，扩大净空，禁止人员进入机械臂和夹具的夹伤/扫掠区域。

## 2. 软件里的限位不是安全功能

关节裁剪、每步增量限制、低通、workspace box、碰撞阈值和 action chunk 平滑只能降低常见软件错误的后果。它们可能被错误配置、进程故障或通信问题绕过，因此不能替代安全系统。

不得为了“先跑起来”而：

- 扩大关节/速度/力矩/工作空间限制。
- 关闭 Polymetis safety controller 或 rate limiter。
- 在 RT 检查失败时继续启动 torque client。
- 自动吞掉 FCI 错误并无限重试 recovery。
- 对未知 checkpoint 直接解锁真机。
- 在无人看守时运行采集或策略控制。

任何 `reset`/`home` 都是实际运动，不是无风险初始化：必须经过当前会话人工放行，禁止在服务启动、重连或 error recovery 时隐式执行。arm/FCI 与 gripper 还必须各自只有一个写 owner；发现残留 runner、调试进程或服务抢占时保持停止。FR3/DROID 参考路线的专项风险见[独立章节](11-fr3-droid-reference.md)。

## 3. 每次实验前检查

### 机械与现场

- [ ] 机器人、底座、工具、相机支架和 GELLO 均无松动。
- [ ] 工作区无人员、线缆、反光/易碎物和未固定物体。
- [ ] 夹爪不会在闭合时夹到人，物体掉落不会造成次生风险。
- [ ] 急停/停止流程已在当天班次验证，观察员知道何时触发。
- [ ] 初始姿态在所有关节软限位内，且离奇异位形、桌面和自碰撞有裕量。

### 版本与配置

- [ ] Robot System 与 libfranka 版本对照官方兼容矩阵通过。
- [ ] 本仓库、fairo、libfranka、GELLO 和 checkpoint 的 commit/path 已记录。
- [ ] 当前 dataset schema、norm stats、policy metadata 完全匹配。
- [ ] 相机角色、RGB/BGR、夹爪极性和单位已用离线样本人工确认。
- [ ] NUC 的 RT、调度权限、网络和 mock benchmark 通过。

### 运行态

- [ ] arm/gripper 服务只监听受控网络，不暴露公网。
- [ ] policy server 只监听远端 `127.0.0.1`，客户端通过 SSH 隧道访问。
- [ ] 首次联调使用只读或影子模式，输出动作不下发。
- [ ] 控制启动时 action queue 为空，首个目标来自当前状态附近。
- [ ] 断开相机、断开 policy、延迟超限和 Ctrl+C 均能进入预期停止状态。

## 4. 强制分阶段门禁

| Gate | 允许的动作 | 通过条件 |
| --- | --- | --- |
| A | 无机器人：单测、mock、数据回放 | schema、形状、单位、metadata、超时均 fail closed |
| B | 机器人上电但制动/FCI 未放行 | 网络、Desk、版本、只读状态正确 |
| C | FCI + Polymetis `readonly=true` | 连续状态稳定，无 RT/丢包错误 |
| D | 低刚度/低速、无工具或安全假负载 | 小幅单关节运动与停止测试通过 |
| E | GELLO/VR 遥操作 | 标定姿态一致，方向/夹爪/边界逐轴确认；recorder 整形与 bridge 单步/加速度硬门禁均验收，deadman 松开立即停止 |
| F | 策略影子模式 | 预测记录可视化通过，无动作下发 |
| G | 短时闭环 | 保守限幅、观察员在位、逐 episode 人工放行 |

任何一项失败都退回前一 Gate。修复后从该 Gate 重新验证；不要仅重启后继续。

## 5. 停止与故障语义

安全默认值必须是停止：

- 图像超时、状态超时、policy 超时、schema/metadata 不匹配、NaN/Inf、动作越界：不发送新目标并终止 episode。
- action queue 枯竭：只能执行经评审的短时 hold 行为，超时后结束控制；不得无限重复旧动作。
- Polymetis 或 FCI 报错：停止当前 policy，锁定故障状态，由现场操作者检查后手动恢复。
- SSH 隧道断开：远端 policy 不得继续影响机械臂；客户端必须在本地超时内停止。
- 日志写盘失败：停止采集 episode，标为无效；不要得到“看似成功但缺帧”的数据。

上游 torque client 可能包含自动 error recovery。这里不把它视为安全机制；生产运行应让重复错误显式暴露，并要求人工确认根因后恢复。

## 6. 首次动作测试

1. 无夹持物、低速、工作区清空。
2. 从当前姿态生成不超过现场批准幅度的单关节目标。
3. 观察方向、追踪误差、网络错误、周期延迟和停止响应。
4. 一次只验证一个自由度，再验证夹爪。
5. 每步都停机检查日志；全部 7 轴通过前不进入遥操作。

`communication_test` 和部分官方示例会移动机器人。它们只能在 Gate D 的现场条件下由操作者手动运行，禁止放入 CI、开机脚本或无人值守健康检查。
